# Descriptive Titles

## Why Titles Matter

A descriptive title helps readers recognize a resource before opening it. When several pages appear in a list, their titles should explain how their subjects differ. Labels such as “Notes,” “Document,” or “Example” provide little guidance because they could describe almost anything.

As explained in [[resource-description/metadata-basics|Metadata Basics]], a title is one part of a resource's description. It should identify the main subject without trying to include every detail. Additional context belongs in the description, while related search terms belong in [[resource-description/tags-and-keywords|Tags and Keywords]].

## Improving a Vague Title

### A Soccer Collection Example

Imagine two pages in a soccer knowledge base. One explains how supporters organize match photographs, while another describes how to record photograph credits. Calling both pages “Soccer Information” hides their differences.

More useful titles would be:

- *Organizing Soccer Match Photographs*
- *Recording Photographer Credits*

Each title identifies a specific purpose. A reader looking for image ownership information can choose the second page without opening both.

## A Simple Naming Process

1. Identify the page's main subject.
2. State the action or question it addresses.
3. Remove words that add no useful meaning.
4. Compare the title with nearby page titles.
5. Check that the content delivers what the title promises.

Specificity should come from accurate information. Do not add an event name, location, or date unless the resource supports it.

## File Names and Display Titles

In this knowledge base, the file name descriptive-titles.md provides a consistent path. Its title property, Descriptive Titles, supplies a readable label on the website. Keeping these roles clear supports both file organization and navigation.

After naming a page, use [[resource-description/metadata-quality|Metadata Quality]] to check whether its title is accurate and consistent.
